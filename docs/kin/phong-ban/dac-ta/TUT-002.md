## 3. Hợp đồng hàm thuần `src/lib/enrollEligibility.ts` (MỚI)

Đặt ở `src/lib` (không phải trong route) vì BU-00 sẽ gộp vào `tutorGate*.ts` sau; `src/lib/tutorGate*.ts` thuộc tut-code (PHAM-VI dòng 26). Import thuần: chỉ `tutorApplicationStatus` từ `@/lib/tutorProfile` — **không import prisma**, để test `t-*-lib.ts` chạy không cần DB.

```ts
import { tutorApplicationStatus } from "@/lib/tutorProfile";

export const ENROLL_TUTOR_PENDING_MESSAGE =
  "Hồ sơ gia sư của bạn đang chờ duyệt — chưa vào lớp với tư cách học sinh được";
export const ENROLL_NOT_STUDENT_MESSAGE = "Chỉ học viên mới redeem mã mời"; // giữ đúng chữ cũ ở redeem/route.ts:29

export type SelfEnrollInput = {
  role: string;                 // User.role: "student" | "admin" (chuỗi, không ép kiểu để nhận cả dữ liệu lệch)
  tutorAppliedAt: Date | null;
  tutorVerified: boolean;
  tutorRejectedAt: Date | null;
};

export type SelfEnrollVerdict =
  | { ok: true }
  | { ok: false; reason: "tutor_pending" | "not_student" };

export function canSelfEnroll(u: SelfEnrollInput): SelfEnrollVerdict;
```

Quy tắc (thứ tự kiểm): `role !== "student"` → `not_student`; rồi `tutorApplicationStatus(u)`.

Bảng chân lý:

| role | tutorAppliedAt | tutorVerified | tutorRejectedAt | status | Kết quả | Ghi chú |
|---|---|---|---|---|---|---|
| student | null | false | null | none | `{ ok: true }` | học sinh thường |
| student | có | false | null | pending | `{ ok: false, reason: "tutor_pending" }` | **ca TUT-002** |
| student | có | false | có | rejected | `{ ok: true }` | bị từ chối → trở lại là học sinh, vào lớp được |
| student | bất kỳ | **true** | bất kỳ | approved | `{ ok: false, reason: "not_student" }` | **Lệch dữ liệu** (duyệt xong phải đổi role sang admin/teacher — xem admin duyệt). QUYẾT chặn: người đã là gia sư được duyệt không tự vào lớp của gia sư khác như học sinh; `reconcileSession` (NC2-033) sẽ kéo role DB về đúng ở lần ghi kế tiếp nên trạng thái này là tạm. Dùng `not_student` (không phải `tutor_pending`) để chữ báo lỗi không nói "đang chờ duyệt" sai sự thật. |
| admin / teacher / chuỗi khác | — | — | — | — | `{ ok: false, reason: "not_student" }` | giữ hành vi 403 hiện có ở dòng 28 |
| student | null | false | **có** | none | `{ ok: true }` | dữ liệu lệch (từ chối mà không có ngày nộp): `tutorApplicationStatus` trả `none` → cho vào; ghi ca test để khoá hành vi |

Bất biến: hàm không có tác dụng phụ, không đọc giờ hệ thống (không so hạn), không ném lỗi.

## 4. Hợp đồng API `POST /api/invites/[id]/redeem` (sửa)

`src/lib/session.ts:9-16`: `SessionPayload` chỉ có `userId/role/adminRole` → **phải đọc DB** một lần, TRƯỚC khi đụng invite/usedCount:

```ts
const me = await prisma.user.findUnique({
  where: { id: session.userId },
  select: { role: true, tutorAppliedAt: true, tutorVerified: true, tutorRejectedAt: true },
});
if (!me) return 401 { error: "Chưa đăng nhập" }           // user đã bị xoá giữa phiên
const v = canSelfEnroll(me);
if (!v.ok) return 403 (xem bảng)
```

Thứ tự phản hồi mới (thay khối dòng 26-30):

| Bước | Điều kiện | Mã | Body |
|---|---|---|---|
| 1 | không session | 401 | `{ error: "Chưa đăng nhập" }` (như cũ) |
| 2 | `session.role !== "student"` | 403 | `{ error: ENROLL_NOT_STUDENT_MESSAGE }` (như cũ, giữ để không tốn truy vấn cho admin) |
| 3 | `canSelfEnroll(me).reason === "tutor_pending"` | **403** | `{ error: ENROLL_TUTOR_PENDING_MESSAGE, code: "TUTOR_PENDING" }` |
| 3' | `canSelfEnroll(me).reason === "not_student"` (lệch dữ liệu) | 403 | `{ error: ENROLL_NOT_STUDENT_MESSAGE }` — không có `code` |
| 4 | mã sai độ dài | 400 | như cũ (dòng 33-35) |
| 5… | `checkInviteValidity`, đã ghi danh (200 idempotent), lớp đóng 409, transaction… | như cũ | như cũ |

Lưu ý thứ tự 3 trước 4: người pending nhận 403 kể cả khi gõ mã rác — đúng ý "chặn người, không chặn mã"; `t-tut-002` kiểm cả ca này.

Bất biến phải giữ (test khoá):
- 403 xảy ra **trước** `prisma.$transaction` → `ClassInvite.usedCount` không tăng, không có `Enrollment`, không `logAction` nào (`class_invite.redeem`, `enrollment.create`).
- `Cache-Control` không bắt buộc (POST).
- Không đổi `src/lib/classInvite.ts`, `planServer.ts`, `enrollment.ts`, schema. Không chạm fee/invoice/sessionBook.
- `t-invites.ts:25-30,38` giữ nguyên kỳ vọng (học sinh thường 200/201, redeem lại không trùng, mã thu hồi ≥400).
- Thêm một truy vấn `user.findUnique` mỗi lần redeem — chấp nhận (redeem là thao tác hiếm, một lần/em/lớp).

Phía UI học sinh (`nhap-ma-lop/page.tsx:65-80`) đã hiển thị `json.error` khi redeem thất bại → câu `ENROLL_TUTOR_PENDING_MESSAGE` tự hiện, **không cần sửa tệp UI**. Nếu stu-dev muốn disable nút sớm hơn, xem mục 6.
