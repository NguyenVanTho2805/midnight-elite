## 3. Schema — chỉ thêm

Không có thư mục `prisma/migrations` ở kho này (đẩy bằng `prisma db push` lúc build) ⇒ **không có tệp migration**; "tệp migration" trong phiếu = chính `schema.prisma`. Sau khi gộp: `npx prisma validate`, đếm dấu `}`, `npx prisma generate`, `db push` lên DB demo, rồi mới `tsc` (BAN-GIAO-CHO-CHU-KHO mục 7). Chạy `t-db-push-guard` và `t-hocphi-schema-additive`.

```prisma
model Course {
  // … thêm ngay sau classStatus (:49):
  // Cách vào lớp (BU-01). null = như trước BU-01 (chỉ vào bằng mã lớp, vào ngay) ≡ "invite_only".
  //   "invite_only" : chỉ mã gia sư phát (hành vi cũ, nay gọi tên)
  //   "open"        : bấm "Vào lớp" trên trang lớp là vào ngay (chỉ cho lớp miễn phí — xem Q1/Q2)
  //   "approve"     : bấm "Vào lớp" / nhập mã → thành yêu cầu, gia sư duyệt
  joinPolicy String?
  // … thêm vào cuối danh sách quan hệ (trước @@index([ownerId]) :87):
  joinRequests ClassJoinRequest[]
}

model ClassInvite {
  // … thêm sau createdBy:
  boundUserId String?                       // mã cá nhân: chỉ tài khoản này dùng được; mã lớp = null
  kind        String  @default("class")     // "class" | "personal"
  @@index([courseId, kind])
  @@index([boundUserId])
}

model ClassJoinRequest {
  id         String    @id @default(cuid())
  courseId   String
  userId     String
  inviteId   String?                         // mã đã dùng để xin (chỉ id, không quan hệ)
  status     String    @default("pending")   // pending | approved | rejected | cancelled
  note       String?                         // lời nhắn của GIA SƯ khi từ chối, ≤ 200 ký tự (kiểm ở joinRequest.ts)
  decidedBy  String?                         // id gia sư duyệt/từ chối (chỉ id)
  decidedAt  DateTime?
  createdAt  DateTime  @default(now())
  updatedAt  DateTime  @updatedAt

  course Course @relation(fields: [courseId], references: [id], onDelete: Cascade)
  user   User   @relation("ClassJoinRequestUser", fields: [userId], references: [id], onDelete: Cascade)

  @@unique([userId, courseId])
  @@index([courseId, status])
  @@map("class_join_requests")
}

model User {
  // … thêm gần createdClassInvites (:961):
  classJoinRequests ClassJoinRequest[] @relation("ClassJoinRequestUser")
}
```
Và chú thích `Notification.type` (:1719) thêm `"join_request_new" | "join_request_approved" | "join_request_rejected"` (chỉ chú thích).

Ghi chú thiết kế:
- **KHÔNG** `Enrollment.status` mới, **KHÔNG** `Course.isFree`. `Enrollment` không đổi một chữ.
- `ClassInvite.createdBy` (bắt buộc, FK cascade) của mã cá nhân = **id học sinh** (chính em tạo ra mã bằng việc bấm Vào lớp); xoá tài khoản em thì mã tự mất.
- Không dùng `@@unique([courseId, boundUserId])` trên `ClassInvite` (mã hết hạn phải đổi mã mới cho cùng cặp ⇒ sẽ vướng). "Một mã cho mỗi cặp em–lớp" bảo đảm bằng khoá advisory + tái dùng dòng (mục 4.4), và có test chạy song song.
- `ClassJoinRequest` một dòng cho mỗi cặp (em, lớp): xin lại = cập nhật dòng, không tạo dòng mới ⇒ lịch sử nằm ở `AuditLog`.
- Chỉ lưu id + lời nhắn của gia sư. Không lưu tên, email, ngày sinh, lý do của em (TRẺ EM = không thu thêm).

```ts
  | { action: "enroll" }
  | { action: "request" }
  | { action: "deny"; status: 403; error: "Mã này gắn với tài khoản khác" };
/** Mã nhập có đưa tới vào lớp, tạo yêu cầu, hay bị từ chối? */
export function redeemOutcome(o: { policy: JoinPolicy; invite: { kind: string | null; boundUserId: string | null }; userId: string }): RedeemOutcome;

/** Học sinh bấm "Vào lớp" có được cấp mã cá nhân / vào ngay không. */
export function joinDecision(o: { policy: JoinPolicy; classOpen: boolean; hasEnrollment: boolean; request: JoinStatus | null }):
  | { action: "enroll" } | { action: "issue_personal_code" } | { action: "already_member" } | { action: "closed" }
  | { action: "invite_only" };               // 409: lớp chỉ vào bằng mã gia sư phát

/** Lớp có được gắn nhãn "Miễn phí" không. Dùng ở MỌI nơi hiện nhãn (không ai tự viết lại điều kiện). */
export function isFreeClass(c: { price: number; tag: string | null; hasFeeRate: boolean }): boolean;   // price === 0 && tag === FREE_CLASS_TAG && !hasFeeRate
/** "open" chỉ hợp lệ khi lớp miễn phí (Q2). */
export function canUseOpenPolicy(c: { price: number; tag: string | null; hasFeeRate: boolean }): boolean;

export function normalizeJoinNote(raw: unknown): string | null;   // trim, bỏ ký tự điều khiển, >200 ⇒ cắt? KHÔNG: >200 ⇒ lỗi
export function joinStatusLabel(s: JoinStatus): string;           // chữ Việt dùng chung cho UI (Chờ duyệt · Đã vào lớp · Chưa được duyệt · Đã huỷ)
```
`redeemOutcome` — 4 ca bắt buộc test: (approve, mã lớp) → request; (invite_only/open, mã lớp) → enroll; (bất kỳ, mã cá nhân của chính mình) → theo `policy`; (mã cá nhân của người khác) → deny 403, **bất kể policy**.

### 4.3 API từng route

Quy ước chung: form ⇒ `POST` + **303**; JSON chỉ khi client gọi `fetch` (`redeem`, `by-code`, các `GET`, `PATCH`). Mọi `GET`/`POST` của gia sư gửi `Cache-Control: no-store`. ## 6. Máy trạng thái

### 6.1 Duyệt vào lớp (`ClassJoinRequest.status`)

```
(chưa có) --apply--> pending
pending   --approve--> approved        [gia sư chủ lớp; cần enrollInTx ok]
pending   --reject---> rejected        [gia sư chủ lớp; note ≤200]
pending   --cancel---> cancelled       [chính học sinh]
rejected  --apply--> pending           [chỉ sau 24 giờ kể từ decidedAt]
cancelled --apply--> pending
approved  --apply--> (từ chối: ALREADY_MEMBER) — TRỪ khi không còn Enrollment (ctx.hasEnrollment = false) ⇒ pending
approved|rejected|cancelled --approve|reject--> NOT_PENDING / ALREADY_DECIDED
pending   --apply--> không đổi (idempotent, không tăng lượt, không thông báo lại)
```
Mọi cặp (trạng thái × sự kiện) phải có kết quả xác định trong `nextJoinState` và được test hết (4+1 trạng thái × 4 sự kiện). `approved` là trạng thái cuối trừ trường hợp em đã rời lớp.

### 6.2 Mã mời (`ClassInvite`)
- *Mã lớp* (`kind "class"`): tạo → dùng được → hết lượt / hết hạn / thu hồi (đúng `checkInviteValidity` hiện có). Với lớp `approve`, mỗi **yêu cầu đang chờ** giữ một lượt (`usedCount+1`), từ chối/huỷ trả lại, duyệt thì lượt mất hẳn.
- *Mã cá nhân* (`kind "personal"`, `maxUses 1`, hạn 30 ngày): cấp (R1) → dùng (gửi yêu cầu: `usedCount 1`) → { duyệt: dùng xong · từ chối/huỷ: `usedCount 0`, mã sống lại, hạn gia hạn khi xin lại · hết hạn: R1 tái dùng dòng, giữ `code`, đặt lại hạn }. Chỉ `boundUserId` dùng được; người khác ⇒ 403 và không đụng `usedCount`.
- Đổi `joinPolicy` không làm mất mã/yêu cầu đang có; `approve → invite_only|open` thì yêu cầu `pending` vẫn chờ gia sư duyệt tay (không tự duyệt).

### 6.3 Buổi (bất biến cần chứng minh cho lớp miễn phí — BU-01 KHÔNG sửa)
`AttendanceSession`: tạo → `state "closed"` (chốt, `POST /api/courses/[id]/sessions/[dateKey]/close {action:"close"}`) → mở lại. Chỉ lúc chốt, và chỉ khi `Course.feeMode` ∈ {per_session, per_hour} **và** có `CourseFeeRate` hiệu lực thì `syncChargesOnClose` mới sinh `FeeCharge` (`feeChargeServer.ts:76`, `:125-137`; `close/route.ts:2-3`). Lớp `price 0`, `feeMode` mặc định, không đơn giá ⇒ chốt buổi sinh 0 dòng phí. Gia sư tự nhập đơn giá hoặc tự lập phiếu tay ⇒ phiếu sinh ra như mọi lớp. Việc tham gia (open/approve) không tạo `FeeCharge`/`TuitionInvoice`.

## 9. Cờ và câu hỏi cho chủ

**TIỀN = trình bày.** Không đổi cách tính phí, không sửa `feeCharge*`/`invoiceServer*`/`sessionBook*`. Chỉ (a) đổi chữ "0đ" thành "Miễn phí" ở hai nơi hiển thị, (b) ẩn dòng "học phí theo bậc thang" ở xem trước mã khi lớp miễn phí. Nhãn "Miễn phí" **không** có nghĩa KiN cấm gia sư thu phí (gia sư vẫn tự nhập đơn giá / tự lập phiếu được — test chứng minh). "Miễn phí = không bao giờ ra phiếu" là quyết định riêng của chủ, ngoài phạm vi.
**TRẺ EM = không.** Duyệt đi qua `enrollInTx` ⇒ `deriveStatusForNewEnrollment` và cổng `KIN_ENROLL_CONSENT_GATE` giữ nguyên; không hỏi thêm ngày sinh, không thêm trường nào ở học sinh; chỉ lưu id + lời nhắn của gia sư. Người học ≥ 17 (BAN-GIAO-CHO-CHU-KHO mục 4): không thêm rào tuổi mới ở đây (rào ở đăng ký/CHỦ-02 là việc khác). Lời nhắn từ chối do gia sư gõ — màn nhập có chữ "đừng ghi thông tin cá nhân của học sinh".
**ĐỔI NỀN = không.** Chỉ Next/Prisma/`notify` sẵn có.
